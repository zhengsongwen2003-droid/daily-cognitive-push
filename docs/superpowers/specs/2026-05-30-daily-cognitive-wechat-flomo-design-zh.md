# 每日认知微信 + flomo 推送系统设计

## 目标

设计一个每日认知训练系统：每天向你推送一篇 3-5 分钟可读完的案例型内容，并同步保存到 flomo，方便长期回看和复盘。

这个系统的重点不是每天发一段鸡汤，而是每天通过一个案例训练一种判断力。每条内容都应该讲清楚一个可迁移的认知模型，并以一个具体问题或一个微行动结尾。

## 推荐产品形态

使用一个轻量自动化流程：每天早上固定时间运行，生成一张认知训练卡片，推送到微信入口，并归档到 flomo。

推荐流程：

1. 每天 08:00 自动运行。
2. 系统选择当天主题。
3. AI 生成一篇 3-5 分钟的案例卡片。
4. 系统检查内容结构、实用性和重复度。
5. 通过稳定的微信入口发送给你。
6. 同步通过 flomo API 或 incoming webhook 保存到 flomo。
7. 记录当天标题和主要认知模型，减少后续重复。

## 微信和 flomo 的分工

微信负责提醒和阅读。它的作用是让你每天真的看到这条内容。

flomo 负责长期沉淀。它会保存每天的认知卡片，并通过标签形成可搜索、可复盘的个人认知库。

第一版推荐使用“企业微信机器人 + flomo API”。这个方案比自动化个人微信私聊更稳定，也更适合长期运行。

## 每日内容格式

每天的卡片固定包含 7 个部分：

```text
#每日认知/主题标签

标题：具体、有冲突感

1. 案例
一个商业、职场、关系、历史或个人选择案例。

2. 关键转折
当事人在什么压力、诱惑或信息不完整的情况下做了选择。

3. 认知模型
解释背后的思维模型，比如沉没成本、损失厌恶、二阶思维、机会成本、激励错位。

4. 常见误判
普通人在类似处境中最容易怎么想错。

5. 迁移到你
把案例映射到工作、赚钱、关系、选择、学习等现实场景。

6. 今日一问
一个让你联系自己现实处境的问题。

7. 微行动
今天可以做的一件小事，最好 10 分钟内能完成。
```

## 每周主题轮换

为了避免每天内容都很像，建议按周轮换主题：

```text
周一：决策偏误
周二：长期主义与复利
周三：人性与关系
周四：商业或产品案例
周五：职场与管理判断
周六：历史、投资或社会案例
周日：本周复盘
```

周日默认不推新案例，而是生成一条周复盘：

```text
本周你训练了哪些判断力
出现最多的认知模型是什么
哪一个问题最值得继续想
下周建议关注哪个主题
```

## flomo 标签

使用固定标签，方便后续搜索和复盘：

```text
#每日认知
#认知偏差
#人生决策
#长期主义
#商业案例
#本周复盘
```

每张卡片都应该包含 `#每日认知`，再额外加 1-2 个具体主题标签。

## 内容质量规则

每条内容发送前都要满足这些规则：

1. 包含全部 7 个固定部分。
2. 阅读时间大约为 3-5 分钟。
3. 只解释一个主要认知模型，不把多个不相关观点硬塞在一起。
4. 避免空泛鸡汤和口号式表达。
5. 必须包含一个具体的“今日一问”。
6. 必须包含一个大约 10 分钟内能完成的微行动。
7. 最近 30 天内不重复同类标题，尽量避免重复同一个具体案例或认知模型。

## 第一版范围

第一版只做最核心的自动化：

1. 每天 08:00 自动运行。
2. 生成一篇每日认知卡片。
3. 推送到企业微信。
4. 同步保存到 flomo。
5. 保存最近 30 天的标题和主要认知模型记录。
6. 推送失败时最多重试 2 次。

第一版不需要网页后台、人工审核队列、数据分析或账号系统。

## 异常处理

如果内容生成失败，系统使用同一主题重试一次。

如果微信发送失败，系统最多重试两次，并记录失败状态。

如果 flomo 保存失败，系统仍然先把内容发送到微信，并稍后重试保存到 flomo。

如果微信和 flomo 都失败，系统把当天生成的内容保存到本地，避免内容丢失。

## 后续增强

第一版稳定后，可以继续增加：

1. 每周 flomo 复盘总结。
2. 简单反馈机制，比如“多来点这种”或“少来点这种”。
3. 根据你的偏好调整主题权重。
4. 本地历史卡片搜索。
5. 发送前人工确认。

## 已确认实现选项

这些实现选项已经确认：

1. 第一版微信入口使用企业微信机器人。
2. 每天推送时间为 08:00。
3. 内容来源使用通用知识生成。
4. flomo API 或 webhook 地址已经拿到，实施时通过环境变量配置。
